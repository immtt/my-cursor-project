**说明**：本版本基于最初 V1.0 原文结构进行增补，保留原业务框架，并融合已确认的匹配机制、覆盖策略、指标口径与异常处理规则。

## 1. 产品背景

同城配送业务中，为优化加盟门店的货物送货效率，引入智能装载及运输排线系统。系统会根据订单数据生成建议的装载方案和运输路线。

为验证系统建议的合理性，需将系统生成的建议数据与实际手动排线数据进行比对分析，评估系统建议的准确性。

### 核心矛盾
- 线下排线人员使用经验装载系数。
- 系统建议使用理论最优系数。
- 两套系数不同时，装载率不可直接对比。
- 可直接对比的核心维度是配送任务重合度、体积差异、里程差异、时效差异。

## 3. 功能需求

### 3.1 核心功能：数据比对

#### 3.1.1 需求描述
系统建议数据与手动排线数据的运单编码体系不同，需通过拼载门店进行跨编码匹配，识别同一配送任务。

#### 3.1.2 匹配机制（已确认）
1. 匹配仅在同一 `route_date` 内进行，不跨日期。
2. 两个表的拼载门店均可能包含多家门店。
3. 门店名称仅汉字，按精确匹配，不做别名映射。
4. 匹配度计算公式：  
   `匹配度 = 重合门店数 / max(系统门店数, 手动门店数)`
5. 匹配状态定义：  
   - 完全匹配：全部重合，匹配度 100%  
   - 部分匹配：部分重合，匹配度 > 0 且 < 100%  
   - 不匹配：无重合，匹配度 0%
6. 冲突处理：同日出现 1 对多/多对 1 时，取最高匹配度唯一配对。
7. 并列处理：若最高匹配度并列，取体积差绝对值最小者。

#### 3.1.3 输出内容（更新）
| 输出字段 | 说明 |
|---------|------|
| 系统运单号 | 来源：系统建议数据 |
| 手动运单号 | 来源：手动排线数据 |
| 匹配状态 | 完全匹配 / 部分匹配 / 不匹配 |
| 匹配度 | 百分比展示 |
| 体积差异 | 系统体积 - 手动体积 |
| 线路一致性 | 归属线路是否一致 |
| 公里数差异 | 系统预计公里数 - 手动预计公里数 |
| 时效差异 | 系统预计时效 - 手动预计时效 |

> 指标口径变更：不再使用“体积差异率”，改为“体积差异”。当手动体积为 0 时，体积差异置空。

### 3.2 核心功能：高德地图路线计算

#### 3.2.1 需求描述
手动排线数据缺少预计公里数和预计时效，需调用高德地图 API 补算。

#### 3.2.2 计算范围
- 仅针对手动排线数据进行高德 API 调用。
- 系统建议数据不重复计算。

#### 3.2.3 处理流程（更新）
1. 地址解析：始发仓库和拼载门店分别进行地理编码。  
2. 路径规划：启用途经点优化，按最优配送顺序规划路线。  
3. 结果回填：写入手动排线数据的预计公里数、预计时效和计算状态。  

#### 3.2.4 失败处理（已确认）
- 单条任务最多重试 5 次。
- 超过重试上限后，记录并返回失败门店。
- 不采用全局事务：允许部分成功、部分失败。

#### 3.2.5 优化策略
- 地址坐标本地缓存，避免重复地理编码。
- 同一仓库 + 同一门店组合可复用路径结果。

### 3.3 辅助功能：比对结果展示

#### 3.3.1 展示内容
1. 整体匹配率统计。  
2. 匹配状态分布（完全/部分/不匹配）。  
3. 体积差异分布。  
4. 线路一致性统计。  
5. 明细列表（筛选/搜索/导出）。  

#### 3.3.2 不展示字段
- 装载率不在结果页展示。

### 5.3 数据匹配算法（更新）

输入：系统建议数据集 S，手动排线数据集 M（同一 `route_date`）  
输出：匹配结果列表 R

算法步骤：
1. 遍历 S 每条记录，提取门店集合 `PS`。  
2. 遍历 M 每条记录，提取门店集合 `PM`。  
3. 计算 `match_score = |PS ∩ PM| / max(|PS|, |PM|)`。  
4. 对每条 S 选取 `match_score` 最高的唯一 M。  
5. 若并列，选取 `|系统体积 - 手动体积|` 最小的 M。  
6. 计算并输出匹配状态、匹配度、体积差异、线路一致性、里程差异、时效差异。  

### 5.4 数据库设计

保留 4 张核心表：`sys_suggest`、`manual_route`、`address_cache`、`compare_result`。  
对比结果表建议字段口径更新：`volume_diff_rate` 调整为 `volume_diff`。

- **未匹配**行与已匹配行**同等**具备该入口，不得隐藏。

### 6.6 路线地图页面

**展示目标**：
- 同屏对比**本行**关联的**系统建议**与**手工排线**的运输路径；缺失的一侧仅绘制存在的一侧。

**地图与线路**：
- 须有**地图窗口**（可缩放、拖拽）。
- **系统**路径：**蓝色**折线；**手工**路径：**红色**折线。
- 线路须为**道路级轨迹**（与高德驾车路径规划返回的折线一致，或由同等服务生成的道路贴合路径），**禁止**仅以仓库与各门店坐标做直线连线示意。
- **起点**均为该行数据中的**始发仓库**；途经点顺序与业务侧采用的**配送顺序**一致（手工侧与补算/途经点优化策略保持一致，与比对所用数据同源）。

**重叠与可读性**：
- 两线空间重叠时须**仍可区分**，至少采用以下之一或组合：**透明度区分**、**线宽/层级**、**线型（如实线/虚线）**、**可切换图层显示单条线路**；须在界面提供**图例**（蓝=系统，红=手工）。

**辅助信息**：
- 地图页须展示与本行一致的关键标识：如系统运单号、手工运单号（可为空）、始发仓库、匹配状态；门店点位建议带序号或顺序提示以便核对排线顺序。

## 9. 验收范围说明

本版本以流程可用和规则正确性为验收重点。  
业务阈值类指标（如 SLA、目标匹配率）暂不纳入本期硬性验收。

### 9.1 路线地图（结果联动）验收规则

以下为**可测试**验收项；全部满足视为该功能验收通过。

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| M-01 | 入口粒度 | 比对结果明细**每一行**均有独立地图入口；入口样式在列表内统一、可识别（如「地图」文案或地图图标）。 |
| M-02 | 未匹配可用 | **匹配状态为未匹配**的行仍具备地图入口，且可正常打开地图视图（不因未匹配而禁用或隐藏）。 |
| M-03 | 单行范围 | 从某行进入地图时，仅展示**该行**对应的系统/手工路径上下文，不与当日其他运单线路混在同屏（除非产品另行定义「聚合视图」，本版以单行为准）。 |
| M-04 | 双色语义 | 系统建议线路为**蓝色**，手工排线线路为**红色**；页面须有**图例**说明颜色含义。 |
| M-05 | 单侧数据 | 若该行仅一侧存在可绘制路径（例如仅系统或仅手工有有效仓库+门店序列），地图上**仅绘制存在的一侧**，图例仍保留双色说明；不得因缺失一侧而空白无图或报错退出。 |
| M-06 | 双侧数据（含未匹配） | 若该行**两侧**均存在可绘制路径，即使匹配状态为未匹配，地图上须**同时绘制**蓝线与红线。 |
| M-07 | 道路轨迹 | 线路几何形状须为**道路贴合路径**（与高德驾车路径规划折线一致或等价效果），**不得**仅用仓库—各门店的直线段连接作为最终呈现。 |
| M-08 | 起点与顺序 | 两条线（若存在）的**起点**均为该行**始发仓库**；途经顺序与**业务数据及补算策略**一致，可与比对结果中使用的里程/时效数据源核对。 |
| M-09 | 重叠可读 | 两线重叠时仍可通过**透明度、线宽/层级、线型差异、图层开关**等至少一种手段区分；验收时随机抽取 3 条重叠明显的样本可人工辨认蓝/红。 |
| M-10 | 基础信息 | 地图页展示与本行一致的**系统运单号、手工运单号（无则明示为空或「—」）、始发仓库、匹配状态**；若展示门店点，应能体现**配送顺序**（序号或顺序连线与折线方向一致）。 |

**非本期硬性验收（可列 backlog）**：地图加载性能指标、离线地图、多日期同屏对比、打印与截图水印等。

## 10. V1.0 -> V1.1 变更记录

### 10.1 规则类变更
- 明确 `route_date` 为排线日期主分桶字段，匹配仅同日进行。
- 明确多门店匹配度公式：重合门店数 / 两边最大门店数。
- 明确冲突处理：最高匹配度唯一配对。
- 明确并列处理：按体积差绝对值最小优先。

### 10.2 指标类变更
- 将“体积差异率”调整为“体积差异”（系统体积 - 手动体积）。
- 明确手动体积为 0 时体积差异置空。
- 明确装载率不在结果页展示。

### 10.3 流程类变更
- 明确高德路径计算使用途经点优化。
- 明确高德失败重试上限为 5 次。
- 明确失败后返回具体失败门店，且允许部分成功。

### 10.4 数据策略变更
- 明确导入策略为同 `route_date` + 同类型整批覆盖（非清库）。
- 明确比对重跑策略为同 `route_date` 结果覆盖。

### 10.5 路线地图（增补）
- 比对结果明细每行提供地图入口；未匹配行同等具备入口。
- 地图页以道路级轨迹展示系统（蓝）与手工（红）路径，起点为始发仓库；详见 §6.6 与 §9.1。

## 11. V1.2 开发决议附录（已确认）

### 11.1 覆盖导入策略
- 采用软失效覆盖，不做物理删除。
- 同 `route_date + dataset_type` 导入新批次时，旧批次标记失效（`is_active=0`），新批次标记生效（`is_active=1`）。
- 覆盖范围仅限目标日期和目标数据类型。

### 11.2 并列匹配打散规则
- 第一优先级：匹配度最高。
- 第二优先级：体积差绝对值最小。
- 第三优先级：手动运单号字典序最小（保证结果可复现）。

### 11.3 高德失败门店口径
- 失败门店按结构化格式记录与返回：
- `[{store, reason, retry_count}]`
- 页面展示失败门店名称、失败原因、重试次数。

### 11.4 导出口径
- 默认导出“当前筛选结果”。
- 可选扩展“导出当日全量”作为次级功能。

### 11.5 数据管理页范围（MVP）
- 本期不支持编辑、删除。
- 本期仅支持查看、筛选、导出。
- 数据修正通过重新导入覆盖完成。

### 11.6 审计能力（本期纳入）
- 导入审计：操作者、时间、数据类型、`route_date`、成功数、失败数。
- 比对审计：操作者、时间、`route_date`、耗时、输出结果条数。
- 高德补算审计：失败门店、失败原因、重试次数、最后重试时间。
