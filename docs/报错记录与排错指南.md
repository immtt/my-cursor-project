# 报错记录与排错指南

本文档记录本项目在开发与验收过程中**真实出现过的报错**、**典型场景**及**已验证的修复手段**，便于再次出现同类问题时快速对照处理（含人工与 AI 助手查阅）。

---

## 使用说明

- 检索时优先按 **报错原文关键词**、**HTTP 状态码**、**浏览器控制台** 或 **界面位置** 匹配条目。
- 涉及端口、路径以仓库当前约定为准：默认前端静态服务 **5173**，后端 **8080**；一键启动见 `scripts/start-dev.sh`，改代码后重启见 `scripts/restart-dev.sh`。
- 修改配置或代码后，若需浏览器验收，应重启前后端后再测。

---

## 排查与入库流程（推荐）

为避免**误以为已解决**、把未验证的结论写进本文档，建议按下面流程处理**新问题**：

1. **用 Debug 方式处理**  
   在 Cursor 中针对「报错、异常、不符合预期」类问题，优先使用 **Debug 模式**（或等价地：先复现、看 Network/终端日志、再改代码），用**可观察证据**（状态码、响应体、栈追踪、curl 复现）定位根因，而不是仅凭推测改一行就认为修好。

2. **验证通过后再写文档**  
   只有在**同一复现路径下**确认：现象消失或变为可接受的业务错误（如 400 + 明确提示），才把本条记入本文档（新建章节或补充「原因 / 修复手段」）。  
   若仅「理论上应该好了」但**未复测**：**不要**写入「已修复」类表述；最多在 PR/会话里备注「待验收」。

3. **每条记录尽量可复核**  
   补充：**报错原文或截图说明**、**界面与操作步骤**、**如何验证已好**（例如：打开某页执行某操作、某 URL 应返回什么）。便于日后 AI 或同事按步骤对照，而不是只抄结论。

4. **与代码提交的关系**  
   修复尽量对应一次清晰提交；文档条目里可写 **提交说明关键词** 或 **涉及文件路径**，便于 `git log` / 检索对齐。

## 1. 导入模板下载：`HTTP 405`（Method Not Allowed）

| 项目 | 说明 |
|------|------|
| **现象** | 浏览器控制台：`GET .../api/import/template` 返回 **405**；或前端提示无法连接/请求失败且状态为 405。 |
| **界面 / 场景** | 「数据导入」页点击 **「导出Excel」**；或直接访问旧路径 `GET /api/import/template?dataset_type=...`。 |
| **原因** | 旧版后端仅注册 **`POST /api/import/{dataset_type}`**。路径 `/api/import/template` 被当成 `dataset_type=template`，但路由只允许 **POST**，对 **GET** 返回 **405**。 |
| **修复手段** | 使用 **`GET /api/import-template?dataset_type=system|manual`**（独立路径，不与 `{dataset_type}` 冲突）。前端请求该地址；后端将 `GET /import/template` 改为 `GET /import-template` 并写在 `POST /import/{dataset_type}` 之前。 |
| **相关代码** | `backend/app/api/routes.py`，`frontend/src/main.js`（导出模板按钮的 `fetch` URL）。 |

### 1.1 扩展：导入成功但「无法加载本批明细（HTTP 405）」

| 项目 | 说明 |
|------|------|
| **现象** | 导入接口返回 `success_rows` 等成功 JSON，页面同时出现红条：**无法加载本批明细（HTTP 405）**。 |
| **原因** | 与上表同类：`GET /api/import/rows` 被 `POST /api/import/{dataset_type}` 占住（`dataset_type=rows`）→ **405**。另若仍 **404**，多为**后端未加载最新 `routes.py` 或未重启**。 |
| **修复手段** | 与 **`import-template`** 同类的独立 URL：**`GET /api/import-batch?...`**；实现见 **`app/main.py`**。执行 **`./scripts/restart-dev.sh`**；`start-dev.sh` 会自检 **「导入后明细 API: OK」**。若仍 404，多为 **8080 上仍是旧进程**，请 **`lsof -i :8080`** 结束后再启。 |

## 2. `Failed to fetch` / 浏览器报 CORS（含 `No 'Access-Control-Allow-Origin'`）

| 项目 | 说明 |
|------|------|
| **现象** | 控制台：`Access to fetch at 'http://127.0.0.1:8080/...' ... has been blocked by CORS policy`；或 **`Failed to fetch`**、**`net::ERR_FAILED`**。顶栏「检测后端」或任意 `fetch` 失败。 |
| **界面 / 场景** | 任意需要调接口的页面；常见：**数据导入**（上传）、**数据比对**、**比对结果**查询。 |
| **原因（多选一或叠加）** | ① 用 **`file://` 双击打开 HTML**，与 `http://127.0.0.1:8080` 跨源且 Origin 异常。② 用 **局域网 IP** 打开前端（如 `http://192.168.x.x:5173`），但接口仍写死 **`127.0.0.1:8080`**，请求落到错误主机。③ 前端端口不是 5173，旧 CORS 白名单未覆盖。④ **POST 上传** 等请求服务端异常中断，浏览器误报为无 CORS 头（见第 3 条）。 |
| **修复手段** | ① 始终用 **`http://127.0.0.1:5173` 或 `http://<本机IP>:5173` 访问前端**；后端与静态服务绑定 **`0.0.0.0`**（`scripts/start-dev.sh`）。② 前端 **`inferApiOrigin()`**：未配置 `window.__API_ORIGIN__` 时，用**当前页面 hostname + 端口 8080** 拼 API 根地址，与局域网访问一致。③ 开发环境在 **ASGI 最外层**增加 **`DevCorsASGIMiddleware`**，对所有 `http.response.start` 补 `Access-Control-Allow-Origin: *`，并单独响应 **OPTIONS** 预检。④ 执行 **`./scripts/restart-dev.sh`** 确保加载最新 `main.py`。 |
| **相关代码** | `backend/app/main.py`，`backend/app/middleware/dev_cors.py`，`frontend/src/main.js`（`API_ORIGIN` / `API_PORT`），`scripts/start-dev.sh`。 |

## 3. 导入 Excel：`POST /api/import/...` 报 CORS / `net::ERR_FAILED`（自检 `/health` 却正常）

| 项目 | 说明 |
|------|------|
| **现象** | 仅 **上传导入** 失败，控制台 CORS 或无 `Access-Control-Allow-Origin`；**`GET /health` 仍 200**。 |
| **界面 / 场景** | 「数据导入」选择文件后点击 **「开始导入」**。 |
| **原因** | 上传了 **非合法 `.xlsx`**（如改后缀、损坏文件），`openpyxl` 抛出 **`BadZipFile`**，未捕获时 ASGI 异常路径可能导致连接异常；浏览器常**误报为 CORS**。 |
| **修复手段** | ① 路由层捕获 **`BadZipFile`**，返回 **400** + 明确文案（「请上传有效的 .xlsx」）。② 保留 ASGI 层 CORS 包装（见第 2 条）。③ 使用页面 **「导出Excel」** 生成模板再填数。 |
| **相关代码** | `backend/app/api/routes.py`（`import_data` 内 `try/except`），`import_service.import_excel`。 |

## 4. `GET /favicon.ico` **404**

| 项目 | 说明 |
|------|------|
| **现象** | 控制台：`GET http://127.0.0.1:5173/favicon.ico 404 (File not found)`。 |
| **界面 / 场景** | 打开任意前端页；浏览器默认请求站点根路径 **`/favicon.ico`**。 |
| **原因** | 静态根目录 **`frontend/`** 下无 **`favicon.ico`**（或无正确 `<link rel="icon">`）。 |
| **修复手段** | 在 **`frontend/`** 放置 **`favicon.ico`**、**`favicon.svg`**，并在 **`index.html`** 的 `<head>` 中增加 `<link rel="icon" ...>`（及 `alternate icon`）。 |
| **相关代码** | `frontend/index.html`，`frontend/favicon.svg`，`frontend/favicon.ico`。 |

## 5. 导入或查询库表：SQLite **`no such column: vehicle_type`**（或类似缺列）

| 项目 | 说明 |
|------|------|
| **现象** | 后端日志或接口返回数据库错误：缺 **`vehicle_type`**（或其它新加字段）。 |
| **界面 / 场景** | **数据导入**、**比对**、**结果查询** 任一涉及读写 `sys_suggest` / `manual_route` 时。 |
| **原因** | 本地仍使用 **升级模型前** 生成的 **`backend/smart_route.db`**（或同路径 SQLite），**`create_all` 不会 ALTER 已有表**。 |
| **修复手段** | 开发环境可 **删除旧库文件** 后重启后端，让表按当前模型重建；或按 **`docs/V1.2_数据库变更清单.md` / `docs/schema.sql`** 执行 **`ALTER TABLE ... ADD COLUMN vehicle_type ...`**。 |
| **相关代码** | `backend/app/models/entities.py`，`docs/V1.2_数据库变更清单.md`。 |

## 6. 启动后端失败：Python 3.9 与类型注解（`str | None` 等）

| 项目 | 说明 |
|------|------|
| **现象** | **`uvicorn` 启动即报错**，提示类型注解语法错误（如 **`str | None`**）。 |
| **界面 / 场景** | 终端执行 `uvicorn` 或 `./scripts/start-dev.sh`。 |
| **原因** | **Python 3.9** 不支持 **`X | Y`** 联合类型（需 **3.10+**），应使用 **`typing.Optional`** 等。 |
| **修复手段** | 将相关注解改为 **`Optional[str]`**、`List[...]` 等 **3.9 兼容**写法。 |
| **相关代码** | 曾涉及 `responses.py`、`routes.py`、`result_service.py` 等（以当前仓库为准）。 |

## 7. 端口占用：脚本或 uvicorn 报 **Address already in use**

| 项目 | 说明 |
|------|------|
| **现象** | 终端：`[Errno 48] Address already in use`，绑定 **8080** 或 **5173** 失败。 |
| **界面 / 场景** | 重复执行 **`start-dev.sh`** / **`restart-dev.sh`**，或本机已有其它进程占用端口。 |
| **原因** | **同一端口**已被占用（含上次未关闭的 Python **`http.server`** / **uvicorn**）。 |
| **修复手段** | 使用 **`./scripts/restart-dev.sh`**（会先释放默认端口再起）；或手动 **`lsof -i :8080 -i :5173`** 后结束对应进程。 |
| **相关代码** | `scripts/restart-dev.sh`，`scripts/start-dev.sh`。 |

## 8. Mac 上默认 **8000** 被占用（隔空播放等）

| 项目 | 说明 |
|------|------|
| **现象** | 后端若仍用 **8000**，本机 **`ERR_CONNECTION_REFUSED`** 或端口冲突。 |
| **界面 / 场景** | 前端默认请求 **`127.0.0.1:8080`**（或按页面主机推断 **:8080**）。 |
| **原因** | 部分 Mac 环境 **8000** 被 **隔空播放接收器** 等占用。 |
| **修复手段** | 项目约定后端默认 **8080**；若改端口，在前端 **`index.html`** 于 **`main.js` 之前** 设置 **`window.__API_ORIGIN__`** 或 **`window.__API_PORT__`**。 |
| **相关代码** | `frontend/src/main.js`，`README.md`，`scripts/start-dev.sh`（`BACKEND_PORT`）。 |
